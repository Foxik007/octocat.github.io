# BATTLE CITY (Танчики, Dendy/NES 1990) — расширенная версия

Полноценная игра в **одном файле `index.html`** (HTML + CSS + JS, без сборки и зависимостей).
Работает офлайн: онлайн-функции включаются опционально своим сервером.

---

## Как запустить

**Способ 1 — просто открыть файл**
Двойной клик по `index.html` (Chrome, Edge, Firefox, Safari). Всё работает, кроме
глобального рейтинга/облака (для них нужны ключи Firebase).

**Способ 2 — локальный веб-сервер** (рекомендуется, даёт корректную работу звука и модулей)
```bash
python3 -m http.server 8000     # затем http://localhost:8000
# или
npx serve .
```

**Способ 3 — Docker (игра + сервер мультиплеера)**
```bash
docker compose up      # игра: http://localhost:8000, WebSocket: ws://localhost:8080
```

## Управление

| Действие | Игрок 1 | Игрок 2 |
|---|---|---|
| Движение | Стрелки ← ↑ → ↓ | W A S D |
| Выстрел | Пробел | Enter |
| Пауза | P или ESC | — |
| Быстрое сохранение | F2 | — |

- **Меню:** ↑↓ выбор, Enter — ок, ←→ — смена уровня, TAB — вкладки, ESC — назад. На телефоне — тапы.
- **Геймпады:** поддерживаются через Gamepad API (левый стик/крестовина, A/X — огонь, Start — пауза).
- **Сенсор:** экранный джойстик + кнопка FIRE появляются автоматически на тач-устройствах.
- **Голос** (Настройки → Голосовое управление): «вперёд», «назад», «влево», «вправо», «стреляй», «стоп».

### На телефоне
- Поле подгоняется под экран (масштаб опускается ниже 1 — раньше этого не было, и поле
  шириной 544 px просто обрезалось по краям).
- **Портретная раскладка**: боковая панель уезжает узкой полосой под поле, поэтому игровое
  поле занимает всю ширину экрана — на iPhone это 390 px вместо 298 с боковой панелью.
  В альбомной ориентации раскладка обычная, как на компьютере.
- Поле прижимается к верху, снизу остаётся место под джойстик и кнопку огня; кнопка
  «назад/пауза» видна всегда, джойстик — только в бою.
- Размеры кнопок считаются от экрана (vmin) и учитывают вырезы и «дом-бар» (safe-area).
- Шрифты меню автоматически укрупняются, когда поле масштабируется вниз.
- Меню управляется тапами: первый тап выделяет пункт, второй подтверждает.
- Курсор главного меню запоминается: вышли из достижений — курсор снова на них.
- В редакторе уровней можно рисовать пальцем с протяжкой.
- Учитывается изменение высоты окна при появлении адресной строки (visualViewport).

## Что в игре

### База — 1:1 с оригиналом Battle City (NES, 1985 / Dendy 1990)
- **Все 35 карт — оригинальные**, а не выдуманные: данные всех уровней перенесены из
  разметки оригинальной игры (13×13 клеток, каждая клетка с маской четвертей).
  Уровень 1 — те самые кирпичные колонны со стальным блоком в центре; лес, вода и лёд
  появляются ровно на тех уровнях и в тех местах, где они были в оригинале.
- **Спрайты местности и орла — попиксельно из оригинала**: кирпич (4×4 px со сменой
  рисунка в шахматном порядке), сталь, вода с двухкадровой анимацией, снег/лёд, лес,
  орёл и разрушенный орёл. Палитра — NES (#6B0800, #9C4A00, #ADADAD, #4242FF, #8CD600…).
- **Сетка разрушения 52×52 юнита по 4 NES-пикселя**, как в оригинале:
  один выстрел выбивает просеку в ширину танка (32 px, по два юнита в каждую
  сторону от снаряда) и на один юнит вглубь — то есть в пробитый проход сразу
  можно въехать. Полная кирпичная клетка прошивается за
  4 выстрела, кирпичная защита орла (толщина в пол-клетки) — за 2, сталь выбивается
  кусками 8×8 px и только танком с тремя звёздами.
- **4 типа врагов оригинала**: обычный (100 очков), быстрый (200), мощный с ускоренным
  снарядом (300) и броневой, держащий 4 попадания и меняющий цвет по мере повреждений (400).
  Плюс наш босс на каждом 5-м уровне.
- **Танк игрока меняется от звёзд**, как в оригинале: без звезды — короткий ствол,
  одна — ствол длиннее с белым набалдашником, две — два ствола (и два снаряда
  в воздухе), три — два ствола и бортовые бронеплиты.
- **У каждого типа свой спрайт 16×16**, а не одна фигура в разных цветах: обычный —
  приземистый с башней по центру, быстрый — длинный ствол и вырезы в корпусе, мощный —
  лобовая плита во всю ширину, броневой — накладные плиты, босс — два ствола.
  Цвета разведены так, чтобы свой танк не путался с чужим: игрок жёлтый, обычный
  серый, быстрый белый, мощный оранжевый, броневой зелёный, босс красный.
- **Состав волны — из оригинала**: для каждого из 35 уровней взято своё соотношение
  типов (например, уровень 1 — 18 обычных и 2 быстрых, уровень 2 — 14/4/2), ровно
  20 танков на уровень; каждый четвёртый мигает красным и роняет бонус (плюс
  8% шанс с обычного танка). Бонус кладётся только на проходимую клетку.
- Поле 13×13 клеток по 32 px (416×416), 60 FPS, фиксированный шаг симуляции.

### Поведение врагов
Враги не бродят наугад: по сетке 13×13 считается расстояние до орла (Дейкстра,
свободная клетка стоит 1, кирпичная 8 — её надо прострелить, сталь и вода
непроходимы), и танк идёт в соседнюю клетку с меньшим расстоянием, то есть по
кратчайшему маршруту, сам обходя стены. Если по маршруту стоит кирпич — пробивает
его, а не отворачивает. Игрока и базу на дистанции до 160 px бьёт прицельно.

Часть танков вместо базы охотится на игрока, иначе все шли бы одной колонной по
одному маршруту. Настраивается двумя числами в `CFG`:

| Параметр | Смысл | Сейчас |
|---|---|---|
| `AI_BASE_SHARE` | доля танков, идущих ломать базу | `0.3` |
| `AI_RANDOM` | доля случайных ходов у них же | `0.55` |

Замерено на уровнях 1/5/12/20/30 при полностью пассивном игроке: база держится в
среднем **41 секунду** (раньше, при случайном блуждании, — около 120). Больше
`AI_BASE_SHARE` или меньше `AI_RANDOM` — враги давят сильнее.
- 3 точки появления сверху (левый край, центр, правый край) по кругу; занятый вход
  пропускается, танки расталкиваются, если корпуса всё же пересеклись, кусты скрывают танки,
  вода непроходима для танков, но пропускает снаряды, на льду танк скользит.
- Бонусы: ★ звезда, 🛡 каска (неуязвимость 5 с), 🚜 танк (жизнь), ⛏ лопата
  (база в сталь на 20 с), 🪙 монета.

- **Взрывы, появление танка, бонусы и щит — тоже пиксельные кадры.** Взрыв раньше
  рисовался прямоугольниками с дробным радиусом и на фоне чёткой кладки выглядел
  размытым пятном; теперь это кадры 16×16 (мелкий взрыв — три, взрыв танка — четыре,
  последние раздуваются на 64 px). Появление — четырёхкадровая звезда, щит
  неуязвимости — мерцающее кольцо из пикселей вместо сглаженной обводки,
  бонусы — иконки в рамке: звезда, каска, танк, лопата, монета.

### Стрельба
- **Перезарядки по таймеру нет** — как в оригинале, следующий снаряд можно послать
  сразу, как только предыдущий во что-нибудь попал. Единственное ограничение —
  сколько своих снарядов одновременно в воздухе: один, и два с двумя звёздами.
  Это правило оригинала: в упор получается ~17 выстрелов за 10 секунд, а если
  палить через всё пустое поле — 7, потому что ждёшь свой же снаряд.
- Дальность не ограничена: снаряд летит, пока во что-нибудь не попадёт.
- Снаряды сбивают друг друга. В дуэли PvP и «Захвате флага» это работает и
  между игроками: раньше условие требовало, чтобы стрелки были разной природы
  (игрок против ИИ), поэтому в дуэли снаряды пролетали сквозь друг друга.
  Снаряды двух танков ИИ, как в оригинале, друг друга не трогают.
- С тремя звёздами снаряд прошивает сталь.
- У врагов таймер перезарядки остаётся — иначе они превращаются в пулемёты.

### Звук
- **По умолчанию играются оригинальные записи** звуков Battle City — выстрел, попадания
  в кирпич и в сталь, оба взрыва, появление и подбор бонуса, пауза, зачёт очков,
  стартовая тема и GAME OVER. Они вшиты в `index.html` как MP3 в base64 (≈92 КБ),
  файл по-прежнему один. Задержка MP3-кодера снимается автоматически: при загрузке
  ищется реальное начало звука, иначе выстрел отзывался бы на ~28 мс позже нажатия.
- **Резерв и альтернатива — модель звукового чипа NES.** Если браузер не декодировал
  записи, звук синтезируется, и это можно включить вручную: Настройки → «ИСТОЧНИК ЗВУКА».
  Синтез не «похожий», а построенный по измерениям оригинала:
  - канал шума — настоящий 15-битный сдвиговый регистр (LFSR), обратная связь бит0⊕бит1
    (период 32767) и «металлический» короткий режим бит0⊕бит6 (период 93);
  - мелодии — импульсный канал со скважностью 50% (определена по гармоникам записей:
    только нечётные, h3 ≈ 0.33, h5 ≈ 0.20);
  - ноты стартовой темы и GAME OVER сняты с записей спектральным анализом по сетке 134.5 мс;
  - частоты LFSR подобраны так, чтобы спектральный центроид совпал с оригиналом:
    выстрел 2298/2273 Гц, взрыв врага 2160/2257, попадание в сталь 1500/1500,
    стартовая тема 2586/2584 Гц.
- Записи идут мимо выходного фильтра 7500 Гц — он нужен только синтезу, иначе верхи
  срезались бы дважды.
- Мотор танка синтезируется всегда: отдельной записи гула в наборе нет.

> Графика рисуется кодом: спрайты заданы матрицами пикселей прямо в `index.html`,
> файлов изображений и данных из картриджа оригинальной игры в проекте нет.
> Звуковые эффекты — это записи из оригинальной Battle City; права на них принадлежат
> правообладателю игры. Для личного и учебного использования это обычная практика,
> но для публикации проекта их лучше заменить (переключатель на синтез уже встроен).

### Монеты и магазин
- Заработок: +10 обычный враг, +25 быстрый, +40 мощный, +50 босс, +100 за уровень, +50 за сохранённую базу.
- Ежедневный бонус: +50 за вход, +10 за каждый день стрика.
- Магазин: **только внешний вид** — 9 цветов танка (открываются по уровням), скины,
  эффекты выстрела и визуальные эффекты. Товары показаны карточками с живым
  превью: цвет и скин — на самом танке, выстрел — летящим снарядом, эффект —
  своей анимацией. Раньше это был текстовый список, и всё покупалось вслепую.
- Эмблемы скинов — 8×8, **у каждой своя палитра** (были одноцветными, и любая
  читалась как белое пятно): пламя красно-оранжево-жёлтое, череп с тёмными
  глазницами, звезда с белым ядром и золотой каймой, дракон с красными глазами.
  Флаг рисуется тремя полосами — российский белый, синий, красный. Свой рисунок задаётся сеткой, по которой рисуют мышью или пальцем,
  с превью танка рядом; флаг выбирается плитками. И то, и другое раньше было
  текстовым `prompt`, куда надо было вводить строку из решёток или номер.

### Журнал и список доработок
- **«ЧТО НОВОГО»** (главное меню и настройки) — список доработок по ревизиям:
  что именно изменилось и в какой версии. Ведётся в массиве `CHANGELOG`,
  новая ревизия добавляется сверху.
- **«ЖУРНАЛ СОБЫТИЙ»** (настройки) — что происходило: старт партии, взятый
  уровень, потеря базы, покупки, нехватка монет и любые ошибки (`window.onerror`
  и необработанные промисы). Хранится в `localStorage` (400 записей), переживает
  перезапуск, выгружается в `battle-city-log.txt`. Ошибки подсвечены красным. Ничего, что влияет на бой, купить нельзя:
  ходовые характеристики танка одинаковы у всех, а усиление даёт только звезда,
  подобранная в бою. Улучшений за монеты (скорость, броня, скорость снаряда,
  лишний снаряд) и покупки монет за деньги в игре нет.

### Режимы
- **Кампания** — 1 или 2 игрока, 35 оригинальных уровней.
- **Кооператив** — вдвоём защищаем одну базу, друг друга подбить нельзя.
- **PvP (дуэль)** — у каждого своя база: у первого внизу, у второго вверху со своей
  кирпичной стеной. Огонь по сопернику включён, танков ИИ нет. Побеждает тот, кто
  разрушит базу соперника или выбьет у него все жизни.
- Бесконечный · Выживание (1 жизнь) · Босс-битва · Захват флага · Свои уровни из редактора.

Кооператив и PvP работают и локально (стрелки + WASD на одной клавиатуре), и по сети.

### Прочее
- Редактор уровней 13×13: рисование мышью, сохранение, экспорт/импорт кодом (base64), запуск на игру.
- 33 достижения с наградой монетами, подробная статистика, локальный топ-10, экспорт/импорт сохранения.
- Ежедневный бонус за вход начисляется сам при запуске (+50 и +10 за каждый день стрика).

## Подключение онлайн-функций (по желанию)

### База данных игроков (в вашем же сервере, без сторонних сервисов)
Отдельно ничего поднимать не нужно: `server.js` — это и комнаты мультиплеера, и база.
Данные лежат в обычном файле `db.json` рядом со скриптом — он создаётся автоматически при
первом запуске сервера (пустой: `{"v":1,"players":{},"scores":[]}`) и наполняется, как только
кто-то зайдёт в игру. Ни Firebase, ни СУБД не требуются.

```bash
npm i ws && node server.js      # адрес указать в index.html: MP_SERVER: "ws://АДРЕС:8080"
```

**Что даёт**
- **Профиль в облаке**: монеты, купленные цвета/скины/эффекты выстрела, постоянные
  надетый вид, статистика, достижения и рекорды. Зашли с другого устройства —
  всё на месте: копите баллы на телефоне, тратите на внешний вид на компьютере.
- **Общий рейтинг** за день / неделю / всё время.
- **Таблица игроков** (вкладка «ИГРОКИ» в рейтинге): у каждого видно лучший счёт,
  максимальный уровень, число фрагов, партий, купленных вещей и достижений; по строке
  открывается карточка игрока.
- **Сводка по всем** (вкладка «ОБЩЕЕ»): сколько всего игроков, партий, фрагов,
  разрушенных блоков, пройденных уровней и накопленных монет.
- **Офлайн-режим полноценный**: без сервера играется всё, прогресс лежит в localStorage
  и уезжает в базу при следующем подключении.

**Учётная запись** заводится автоматически при первом запуске (идентификатор + секретный
токен хранятся у вас в браузере). Перенос на другое устройство: Настройки → «КОД ПЕРЕНОСА
ПРОФИЛЯ», на втором устройстве — «ВОЙТИ ПО КОДУ ПЕРЕНОСА».

**Разрешение конфликтов** — по номеру ревизии, который растёт только вперёд. Если
устройство пытается сохранить устаревшую версию, сервер её отклоняет, а клиент забирает
свежую. Побеждает то устройство, которое сохранилось последним, — при одновременной игре
с двух устройств прогресс более раннего сеанса будет перезаписан.

**Ограничения по безопасности**: сервер обрезает строки, ограничивает числа и списки,
чужой токен отклоняется. Но игра считается на клиенте, поэтому база доверяет присланным
цифрам — от целенаправленной накрутки это не защищает. Для домашнего сервера этого
достаточно; в `db.json` попадают токены игроков, поэтому его не стоит коммитить (уже
внесён в `.gitignore`).

### Мультиплеер
Реализована схема **авторитетного хоста**: игру целиком считает тот, кто создал комнату,
и 20 раз в секунду рассылает снимок мира; второй игрок шлёт только свой ввод и рисует
принятое состояние, локально предсказывая движение собственного танка. Поэтому оба
всегда на одной карте, видят одни и те же танки и каждый управляет своим.

**Запуск сервера**
```bash
npm i ws && node server.js            # или docker compose up
```
В `index.html` укажите адрес: `MP_SERVER: "ws://АДРЕС:8080"` (в проде — `wss://`).
Сервер ничего не считает — он раздаёт номера игроков и пересылает сообщения комнаты.

**Чат.** Переписка хранится в `localStorage` (до 300 сообщений) и переживает
перезапуск: раньше сообщение всплывало плашкой на две секунды и пропадало
насовсем. Экран «МУЛЬТИПЛЕЕР → ЧАТ» показывает историю с разбивкой по дням и
временем, свои реплики выделены цветом; оттуда же можно написать сообщение,
выгрузить переписку в `battle-city-chat.txt` (и в буфер обмена) или стереть её.
Текст сообщений экранируется — присланная по сети разметка выводится как текст.

**Как играть**: Мультиплеер → создать комнату (кооператив или PvP) → передать второму
игроку 4-значный код → он выбирает «Подключиться по коду». Партия стартует сама,
как только второй вошёл. В правой панели видно роль (HOST/GUEST).

**Что сделано для устойчивости связи**
- Снимки складываются в очередь, а не перезаписывают друг друга: если у второго игрока
  просядет частота кадров, ни одно изменение карты не потеряется.
- Раз в 3 секунды передаётся полный слепок местности (сжатие повторами, ~0.3 КБ):
  любое расхождение из-за обрыва или переподключения чинится само.
- Снимки идут во всех состояниях, включая заставку, паузу и конец партии.
- **Перезапуск общий**: «ИГРАТЬ СНОВА» перезапускает партию сразу у обоих. Хост
  объявляет старт тем же сообщением `begin`, что и при первом запуске; гость
  просит хоста сообщением `rematch`. Если соперника в комнате уже нет —
  перезапуск обычный, локальный.
- Трафик хоста — около 1 КБ/с. Проверено при пинге 160 мс с джиттером и потерей 2%
  пакетов: карта сходится точь-в-точь, свой танк расходится в среднем на 1.2 px.

**Протокол** (сервер только пересылает сообщения внутри комнаты)
```
-> create/join {room,name}      <- welcome {index,mode}   <- peer {players}
-> begin {mode,level}           -> in {k}  (ввод одним байтом)
-> snap {...}  (снимок мира)    -> chat / ping / pong
-> rematch {level}  (гость просит перезапуск, решает хост)
```

## Структура кода (`index.html`)

| Раздел | Что внутри |
|---|---|
| 1–4 | Конфигурация, утилиты, пиксельный шрифт 5×7, звуковой движок (модель APU NES) |
| 5 | Палитра NES и рисование спрайтов (танки, орёл, скины) |
| 6–8 | Сохранение/профиль, каталог магазина, достижения |
| 9 | 35 оригинальных карт, спрайты местности/орла, класс `Field` (разрушение 52×52, кэш отрисовки) |
| 10 | `Bullet`, `Tank`, `Player`, `Enemy`, `PowerUp`, `Explosion` |
| 11–12 | Ввод (клавиатура, геймпад, сенсор, голос) |
| 13 | `Game` — игровой цикл, спавн, режимы, HUD |
| 14–16 | Рейтинг, облако (локальная БД на своём сервере), сетевой мультиплеер, ежедневки |
| 18–20 | Интерфейс (меню, магазин, редактор), главный цикл, запуск |

Статичная местность рендерится в offscreen-канвас и перерисовывается только при изменении карты —
это держит стабильные 60 FPS даже на слабых устройствах.
